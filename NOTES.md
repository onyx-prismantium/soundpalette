## M1 — Decode, loudness, fixtures

- The vendored miniaudio + stb_vorbis implementation lives in its own translation unit
  (`core/src/vendor_audio_impl.cpp`), built as a separate `OBJECT` library that does **not**
  get `sp_set_warnings()` applied. §13.6's warning-clean requirement is about our own code;
  ~96k lines of vendored third-party source is not written to be `-Wall -Wextra -Werror` clean
  and enumerating suppressions for it would be pointless busywork. `audio.cpp` itself (our
  code, calling the vendored API) is fully warning-clean under `-Wall -Wextra -Werror`.
- Source sample rate/channel count is queried with a throwaway `ma_decoder` opened with a
  pass-through config (format/channels/rate = 0), read via `ma_decoder_get_data_format`, then
  discarded — deliberately *not* using `ma_decoder_get_length_in_pcm_frames`, since miniaudio's
  own header docs say it always returns 0 for Vorbis (stb_vorbis push-mode limitation).
  Duration instead comes from actually streaming all frames through the resampling decoder
  (§6's target 48 kHz mono) and counting them, which works uniformly across all four formats.
- §6/§7 do not give closed-form equations for the darkset/bright_outlier fixtures' one-pole
  low-pass/high-pass filters (only "one-pole low-pass fc 300 Hz applied twice" etc.). Used the
  standard textbook one-pole forms: LPF `y[n] = a*y[n-1] + (1-a)*x[n]`, HPF (leaky
  differentiator) `y[n] = a*(y[n-1] + x[n] - x[n-1])`, both with `a = exp(-2*pi*fc/fs)`. These
  only need to produce a qualitatively low/high-passed noise signal for the M4 lint-outlier
  demo (dark = warm/low-passed, bright_outlier = bright/high-passed); no downstream test in
  §11 depends on the filter's exact numeric transfer function.
- Test fixture WAVs are generated by `genfixtures`, not committed to git (`.gitignore`) — only
  the golden manifest/SVG under `tests/golden/` (added in M3/M4) are committed, per §3's comment
  ("committed golden manifest + golden SVG"). `CLAUDE.md`'s Test section documents the
  genfixtures + make_lossy.sh regeneration step.
- Spot-check: `sine997_cal.wav` (997 Hz sine, peak 0.1001) measured `lufs_i` via
  `measure_loudness` = calibration target -23 LUFS within the ±0.5 tolerance (unit test
  `loudness/calibration` passes) — sanity-checks the libebur128 wiring end to end.

Gate verified: `ctest -R "decode|loudness"` → 3/3 pass (`decode/duration`, `decode/lossy`,
`loudness/calibration`); full clean rebuild produces zero compiler warnings.
